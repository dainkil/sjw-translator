# ADR-024: 산출물 재현성 — 무엇을 고정하고 무엇을 포기하는가

- 상태: 승인 (공개 서빙 1차)
- 날짜: 2026-09-29

## 배경

"나중에 같은 환경이면 이 모델을 다시 똑같이 만들 수 있어야 한다"가 요구사항이다. 배포를 끝내고
점검해 보니 그 요구가 실제로는 성립하지 않았다:

1. **업스트림 모델 리비전이 고정돼 있지 않았다.** `export_onnx.py`가 `ddokbaro/SillokBert-NER`를
   태그 없이 받았다. 저자가 가중치를 갱신하면 같은 명령이 다른 모델을 만들고, 그 순간
   `model_version`이 바뀌어 캐시 키가 갈라지고 벤치마크 수치가 그 산출물에 대해 성립하지 않는다.
2. **서빙 런타임 의존성이 `>=`로 열려 있었다.** 2026-09-29 빌드는 `transformers>=4.44`로
   **5.17.0**을 받았다 — 메이저 버전 상승이 조용히 들어왔다. 토크나이저 동작이 달라졌다면
   NER 출력이 바뀌었을 것이고, 아무도 몰랐을 것이다.
3. **`uv.lock`은 있었지만 서빙 이미지가 쓰지 않았다.** export 환경만 고정돼 있고 런타임은 맨몸이었다.

즉 "재현 가능"이라고 믿고 있었을 뿐 근거가 없었다.

## 선택지

1. **아티팩트 보존 우선** — 빌드된 이미지를 정본으로 삼고 다이제스트로 고정한다. 재빌드는 보장하지 않는다.
2. **빌드 재현 우선** — 베이스 이미지 다이제스트까지 전부 고정해 소스에서 비트 동일 재빌드를 노린다.
3. **현행 유지** — 태그만 기록한다.

## 결정

**(1)을 강한 보장으로, (2)를 최선 노력으로 둔다. 두 층을 구분해 명시한다** — 뭉뚱그리면
"재현된다"는 말이 검증 불가능한 주장이 된다.

"다른 것이 만들어졌는데 모르고 배포"가 구조적으로 불가능하다. 실측으로 확인했다:
리비전·핀 고정 후 재빌드 시 `onnx-d66923a5` 동일.

### 재현되지 않는 것 (정직하게)

- **번역 LLM.** `gemini-3.1-flash-lite`는 외부 API다. 버전을 고정할 수단이 없고, 같은 입력에
  같은 출력을 주지도 않는다(ADR-013이 이 비결정성 위에 세워져 있다 — chrF가 라운드 간
  3포인트까지 흔들린 실측). **번역 결과의 재현은 처음부터 목표가 아니다.** 재현 대상은
  파이프라인과 NER 모델이고, 번역 품질은 지표의 분포로 관리한다.
- **베이스 이미지 패치.** `python:3.11-slim` 등은 부동 태그다 — 아래 "버린 대안" 참조.

## 버린 대안과 그 이유

- **베이스 이미지까지 다이제스트 고정(2의 완전판)**: 비트 동일 재빌드에 가장 가깝다. 버린 이유는
  **유지비**다. 다이제스트를 박으면 보안 패치가 자동으로 들어오지 않아 사람이 주기적으로 올려야
  하는데, 과정 기간 한정 배포(ADR-022)에 그 루틴을 만들 근거가 없다. 대신 **그때 무엇이었는지를
  위 표에 남겨** 사후 추적은 가능하게 했다. 장기 운영으로 넘어가면 이 결정을 먼저 뒤집는다.
- **모델 가중치를 git LFS로 커밋(재현 대신 보존)**: 174MB를 저장소에 넣으면 리비전 고정 문제가
  사라진다. 버린 이유는 무료 LFS 한도와 clone 비용이고, 애초에 `export_onnx.py` +
  리비전 + 지문 검증이 같은 보장을 훨씬 싸게 준다. 업스트림이 삭제되면 이 판단은 무효다
  (재검토 조건 참조).
- **현행 유지(3)**: 위 배경 2번이 반례다. 메이저 버전 상승이 조용히 들어왔고 아무 경보도 없었다.

## 재검토 조건

- **업스트림 모델이 삭제·비공개 전환되면** 즉시 가중치 보존 방식(LFS 또는 외부 스토리지)으로 전환한다.
  현 설계는 HF에 그 리비전이 남아 있다는 전제 위에 있다.
- **과정 종료로 Harbor가 회수되면** 층 1이 사라진다 — 그 전에 이미지를 외부로 내보내거나
  층 2만으로 운영할 수 있는지 확인한다.
- **장기 운영·다수 사용자로 넘어가면** 베이스 이미지 다이제스트 고정과 패치 루틴을 도입한다.
- 재빌드에서 지문이 달라지면 그것이 이 ADR의 실패 신호다 — 무엇이 움직였는지 찾아 이 표를 갱신한다.
