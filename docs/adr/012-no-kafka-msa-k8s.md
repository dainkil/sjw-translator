# ADR-012: Kafka / 마이크로서비스 세분화 / K8s 배제

- 상태: 승인 (§7 선배제의 확정 기록) · **주석 (공개 서빙 1차, 2026-09-28 — K8s 항목의 범위를 명확히 함. 맨 아래)**
- 날짜: 2026-09-01

## 배경

백엔드 포트폴리오에서 Kafka·MSA·K8s는 "있어 보이는" 기본 옵션이라 도입 유혹이 상수로 존재한다.
이 프로젝트가 그것들을 쓰지 않는 이유를 실측으로 고정해 둔다.

## 선택지

1. **모듈러 모놀리스 (현행)** — common/api/worker 3모듈, docker compose, 단일 노드
2. Kafka + 서비스 세분화 + K8s

## 결정

**선택지 1.** 근거는 전부 실측이다:

- **처리량 상한 = 외부 무료 quota다.** 배치 처리량 23 jobs/min에서 워커 1대와 2대가 동일했다(23.4 vs 23.1 — docs/benchmarks.md). 스케일아웃할 축 자체가 없다 (D11/ADR-021).
- 큐 깊이가 병목인 적이 없다 — Redis Streams로 충분함은 ADR-014에서 확정.
- 배포 단위 분리(MSA)의 전제인 "팀별 독립 배포 요구"가 1인 프로젝트에 존재하지 않고, K8s의 전제인 "노드 풀"이 없다 (배포 타겟은 무료 단일 인스턴스 — §15, ADR-022).

## 버린 대안과 그 이유

- **Kafka**: 파티션 병렬성은 quota 상한 아래에서 무의미하고, 리플레이는 Postgres job 테이블이 이미 제공 (상세 ADR-014).
- **서비스 세분화**: NER 서버 분리(ADR-002)처럼 **런타임이 다르다는 실제 이유**가 있을 때만 분리한다. 같은 JVM 코드를 네트워크 경계로 쪼개면 §2.1에서 지연 예산을 깎아먹는 왕복만 늘어난다.
- **K8s**: 오케스트레이션할 복제본이 없다 (워커 1대 확정). `docker compose up` 한 줄이 배포 스토리 전부인 것이 이 규모의 정답이다.

## 재검토 조건

- 유료 전환으로 quota 제약이 사라지고 동시성 수백 이상이 실측 요구가 되면 (그때 첫 단계는 K8s가 아니라 워커 다중화 — ADR-021의 재검토 조건 참조).

---

## 주석 (공개 서빙 1차, 2026-09-28) — "K8s 배제"가 배제하는 것

공개 서빙 1차에서 이 시스템은 실제로 쿠버네티스(SKALA EKS `skala-gj4`, ADR-022 개정)에 올라간다.
표면적으로 이 ADR과 어긋나므로 범위를 명확히 해 둔다. **결정은 뒤집히지 않았다.**

이 ADR이 배제하는 것은 **아키텍처로서의 K8s** — 즉 "스케일아웃할 축이 없는데도 오케스트레이션을
도입하는 것"이다. 본문의 근거가 그대로 유효하다: 워커 1대와 2대의 처리량이 같았고(23.4 vs 23.1),
상한은 여전히 외부 무료 quota다.

배제되지 않는 것은 **배포 수단으로서의 K8s**다. 제공된 네임스페이스에 평범한 kustomize로 올리는
것은 `docker compose up`의 자리를 대신할 뿐 아키텍처를 바꾸지 않는다. 실제로 올라간 형태가 그 증거다:

| 항목 | 상태 |
|---|---|
| 워커 replicas | **1** (`strategy: Recreate` — 롤링 중복은 이중 과금, ADR-021/D11) |
| api replicas | 1 |
| HPA / 오토스케일링 | 없음 |
| Helm / 오퍼레이터 / 서비스메시 | 없음 — kustomize 평문 YAML |
| 서비스 분해 | 그대로 (common/api/worker + NER. NER 분리는 런타임이 달라서, ADR-002) |
| Kafka | 없음 — Redis Streams 그대로 (ADR-014) |

즉 "이력서용 K8s"는 여전히 없다. 복제본 수를 늘리지 않았고, 오케스트레이션이 풀어주는 문제를
가진 척하지 않는다. 바뀐 것은 실행 위치뿐이다.

**이 주석이 무효가 되는 신호:** replicas를 1보다 크게 잡거나 HPA를 붙이는 순간, 그것은 배포 수단이
아니라 아키텍처 변경이다 — ADR-021을 먼저 열어야 한다.
